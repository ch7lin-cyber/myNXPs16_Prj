# DTDM04 Feedforward 參數與架構對照

## 摘要

實作增補：L04 FbFeedforward 已完成三階段與事件／Force核心並通過Host／ASan／UBSan；指數採明確tau與有限段正規化，第三段線性回零，取消與重觸發採專案契約。以下未實作／待定為原盤點背景，目前以 [正式規格與方塊圖](../../_Modules/PlatformCore/L04_FunctionBlock/Control/FbFeedforward/README.md) 為準。SYSTEM／L05、PID加總／熱冷分配、追蹤及Register／NVM／MCU未完成。

2026-10-22：依使用者提供的 Feedforward Register 表，配合先前讀取的 DTDM04 v1.5 第 5.1.8 節（頁 5-11～5-13），確認此為事件觸發的三階段有號 MV 補償，不是一般設定值斜率或純加總。

**目前沒有事件觸發前饋 FB，尚未實作。** FbWeightedSum 可加總，FbLeadLag 有動態運算，但不代表已有本功能的波形／狀態機。此次只整理文件，不新增演算法、Register 或實體輸出。

以本專案架構為主：SYSTEM Event 提供觸發，L05 選通道與安排呼叫，L04 產生 FF 補償量，再與 PID 結果形成候選 MV，最後由既有 SYSTEM／Safety／輸出服務決定是否輸出。前饋不可繞過停用、故障或安全抑制。

## 原表欄位

原表位址依十六進位解讀，Table Index 不是 Modbus 位址。下表為 CH1 起點，CH2～4 依序加 1～3；本專案不直接沿用位址。時間設定的 1 單位=100 ms，補償的 1 單位=0.1%。

| 欄位 | CH1 位址 | 範圍／預設 | 已知意義 |
|---|---|---|---|
| Feedforward Output | 0x1820 | −1500～1500／0，唯讀 S16 | 當次 FF 補償，對應 −150～150%；不是限制後的最終硬體輸出。 |
| Delay D1 | 0x1824 | 0～30000／0 | 事件觸發後延遲，0～3000 秒。 |
| FF1 Time T1 | 0x1828 | 0～30000／0 | 第一階段時間。 |
| FF1 Output Type | 0x182C | 0～1／0 | 0=Instant Step，1=Exponential；由 0 到 FF1 目標。 |
| FF1 Output Value | 0x1830 | −1500～1500／0 | 第一階段目標，0.1%。 |
| FF2 Time T2 | 0x1834 | 0～30000／0 | 第二階段時間；由上一個 FF 值到 FF2 目標。 |
| FF2 Output Type | 0x1838 | 0～1／0 | 0=Instant Step，1=Exponential。註解寫 FF1 但描述 FF2，按欄位記錄，不擴大解讀。 |
| FF2 Output Value | 0x183C | −1500～1500／0 | 第二階段目標，0.1%。 |
| FF3 Time T3 | 0x1840 | 0～30000／0 | 第三階段由上一個 FF 值回到 0；原表沒有 FF3 曲線類型或額外目標值。 |
| Force Active Time Tx | 0x1844 | 0～32000／0 | 自觸發起算，0～3200 秒；0 表示依事件位準運作，細則如下。 |
| Reserved | 0x1848、184C 起 | 保留 | 不解讀為啟用開關、FF3 型態或新的波形參數。 |

所有欄位預設 0。表中沒有獨立來源選擇或 ENABLE，不代表產品不需要這兩個概念；來源與啟用由外層配置，L04 仍應有明確 enable。

## 正常波形與階段

一般順序：Idle → D1 Delay → Stage1 → Stage2 → Stage3 → Complete／Idle。正常完成時 FF 回到 0。

- 第一階段從 0 向 FF1 目標動作；步階模式立即切至目標，並維持該段設定時間。
- 第二階段從前一個實際 FF 值向 FF2 目標動作，不先歸零。
- 第三階段從前一個值回到 0。若前值為負值，回零是數值上升，因此不應一律使用只會降低數值的邏輯。
- 手冊指出持續時間 0 的階段會跳過；跳過是否同時套用該段目標，尤其全零時間時，仍需在專案契約中明訂，不能造成一次掃描的非預期脈波。

原表沒有指數公式、時間常數或到期精確命中政策，不能直接將 T1／T2 當作 tau，也不能只憑 Exponential 就宣稱與 FbLeadLag 等價。FF3 的衰減曲線同樣未由本表定案。

## 強制時間與事件訊號

已讀手冊說明：Tx=0 時依 Event 位準運作；Tx 非零時，Event 提早轉低仍可強制執行到指定時間，若 Tx 小於 D1+T1+T2+T3，到 Tx 終了時補償歸零。

因此 **Tx 從事件觸發開始算，包含 D1，不是 Stage1 開始才計時**。Tx<D1 時可能根本來不及產生補償。

仍待明確的情況：Tx 大於正常波形總長時是否保持某個狀態、Tx 結束但 Event 仍為高時是否能繼續、Event 提早轉低時立即歸零還是進入 Stage3、重觸發採忽略／重啟／延長，以及完成後持續高電位是否重跑。這些需結合時序圖或定義專案政策，不能將 Tx 簡化為一般最短 ON 時間而忽略波形結束。

## 與 PID 及輸出鏈的關係

依原表 Total MV=PID MV＋FF MV，補償可以為正或負；中間加總須使用足夠位寬，不能先轉成無號或先夾成 0～100%。

例如 PID=40.0%、FF=+15.0%，候選 MV 為 55.0%；FF=−15.0% 時候選為 25.0%。若結果超過允許範圍，依產品定義的控制限幅與安全輸出路徑處理，不直接當成硬體可輸出的命令。

尚需定案熱／冷雙輸出補償到 MV1、MV2 或合成有號控制量的規則，以及飽和時 PID anti-windup／追蹤、手動／AT／Cascade 期間前饋是否允許。現有 MV1／MV2 不可直接假設共用一個有號加法。
