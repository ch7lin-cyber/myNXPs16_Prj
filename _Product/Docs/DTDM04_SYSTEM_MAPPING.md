# DTDM04 2000h 系統／串機參數對照（暫存規劃）

## 摘要

本表是系統參數，不代表需要新增一個涵蓋全部功能的 L04 FB。量測、控制命令、通訊與拓撲分別融入既有服務；以本產品架構為主，DTDM04 位址與數值只作功能參考。本次僅更新文件，未修改程式或通訊行為。

200Ch 已確認 0=10 ms、1=50 ms，預設 50 ms；2052h 為 PID 更新週期 1 秒／100 ms／10 ms。兩者是不同層的週期，連動觸發條件仍未完整定義。200Bh 的 400～1000 ms 模組掃描不適合直接套用為本專案全部控制資料更新週期。

## 取樣、控制與傳輸週期

本產品已規劃 10 ms 系統排程與 AD7124 100 Hz，仍須用實際樣本序號／時間戳確認資料更新。PID 執行、量測更新與跨模組資料傳輸分開配置；重新計算不代表取得新量測。

2052h=10 ms 時，來源也必須提供符合設計要求的資料時效。若來源 50 ms 才更新，是否維持前值、僅新樣本計算或拒絕該組合，要依演算法離散時間契約定義，不能靜默混用。原表僅提供「連動取樣週期為 0=10 ms」的註解，尚未說明是否所有 2052h 選項都強制寫入 200Ch、何時拒絕或如何恢復。

串機的控制資料更新應依本專案內部 CAN／RS-485 能力、重要性與時效需求設計。200Bh 的慢掃描可參考為管理／低速資料用途，但不是直接採納的排程。DO 命令與回報、DI 狀態、遠端 PV、拓撲發現可有不同週期；各來源均需在線狀態、時間戳／序號、逾時及重連規則。L04 只接收已整理的值與品質，不處理總線。

## 單位與狀態不能混用

°C／°F 絕對溫度：°F=°C×9/5+32；溫差、PB、Alarm 相對界限僅乘 9/5，不加 32。斜率另帶時間單位。內部維持 °C 與 0.001°C 目標，切換 UI 單位不改寫原物理設定；類比電壓／電流及無單位值不作溫標換算。

2010 若採既有 FbAlarm enable=false，現有契約會清除部分運行狀態並保留峰值；這不必然等於使用者期待的「待機暫停但保留手動鎖存」。需先定義停評估、輸出遮蔽、保持鎖存及恢復策略，再接入。Safety 保護亦不能由一般警報待機開關一併停用。

上電策略需區分保存的使用者 RUN 請求、實際控制狀態與輸出許可。所有通道命令須定義部分接受時的回報；WO 命令不以單一儲存值假裝各通道已成功執行。

站號偏移加旋鈕的理論最大值為 224+15=239，但合法站號仍依本產品協定驗證，並在命令完成／配置套用的明確邊界切換。bit 8 的來源、取樣時機及板型差異未明，不直接實作。

## 待確認

- 2052h 與 200Ch 的連動條件，以及修改週期時 Ti／Td 物理時間是否保留。
- 2003 的 F 上限是否代表四通道遮罩；2008 註解 bit 8 實際來自哪個設定／硬體。
- 200Bh 掃描涵蓋哪些資料；實體位置與首台站號如何探索、離線與重連如何更新。
- 2010 STOP 時的鎖存、成立延遲與恢復語意；2012 靜態 SV 在程序／串級時的顯示來源。
