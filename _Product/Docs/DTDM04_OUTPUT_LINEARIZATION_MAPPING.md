# DTDM04 輸出折線表對照

## 摘要

2026-10-22：依使用者提供的 Output Linearization Parameters 表格，確認產品標示 10 組，每組有來源功能／通道、OFF／線性內插／步階、來源與結果監看、Offset、輸出單位及 10 個 X／Y 點。此次實際提供 SET1～SET4 的位址，不將 SET5～10 的位址推算值當作已確認資料。

現有 FbLinearization 可重用線性內插核心，但沒有步階與 Offset，亦沒有產品來源路由、10 組管理或實體輸出串接。**本次只是規格對照，未修改程式或 Register。**

## 已確認欄位與分層

原表 Table Index 與 Modbus 位址不同；以下以 SET1 為例，位址解讀為十六進位。其他已提供組別的起點為 0x1870／1890／18B0，間距 0x20；此配置不限制通用 L04 的組數。

| 欄位 | SET1 位址 | 原表定義 | 本專案責任 |
|---|---|---|---|
| Source Function | 0x1850 | 0=Off、1=MV1、2=MV2、3=PV、4=SV、5=dynaSV、6=PV−SV | L05 選來源與檢查有效性／量綱，L04 只接收數值。 |
| Source Channel | 0x1851 | 0=Off、1～4=CH1～4 | L05 來源路由，不將硬體通道編號放進 L04。 |
| Operation Type | 0x1852 | 0=Off、1=Interpolated、2=Stepped | L04 的轉換模式；通用內插已有，步階尚缺。 |
| Source Value | 0x1853 | 唯讀 S16 | L05 記錄當次選定來源值及有效性。 |
| Output Value | 0x1854 | 唯讀 S16 | L05 發布轉換結果，非直接寫 DAC／PWM 的命令。 |
| Output Offset | 0x1855 | S16，−9999～9999，預設 0 | 運算層參數；單位與套用／限制順序需定義。 |
| Output Unit | 0x1856 | 0=來源值單位、1=無單位、2=MV（0.1%）、3=溫度（0.1°C） | L05 維護量綱與刻度；單位標記不等於自動將百分比換成溫度。 |
| Input Points 1～10 | 0x1857～1860 | S16，−32000～32000，預設 0～9 | L04 唯讀點表的 X；來源與 X 必須同刻度。 |
| Output Points 1～10 | 0x1861～186A | S16，−32000～32000，預設 0～9 | L04 點表的 Y；與 Output Unit 及 Offset 同刻度。 |
| Reserved | 0x186B～186F | 保留 | 不推定為點數、限制或其他未提供功能。 |

這裡的十個輸出點是曲線 Y 值，不是十個實體輸出。十組 SET 是產品容量，也不等於十個 Sensor 通道。

## 現有程式與缺項

| 能力 | 現況 |
|---|---|
| X／Y 點表、線性內插 | FbLinearization 已有。 |
| X 嚴格遞增、有限數值驗證 | 已有；不默認等同原設備跳點策略。 |
| 超出範圍的 CLAMP／ERROR | 已有；原表未說明設備邊界行為，不能宣稱相容。 |
| 點數由呼叫端指定 | 已有 count，不寫死十點。 |
| Stepped 步階 | 尚未實作。 |
| Output Offset | 尚未納入折線 FB；不能因有 WeightedSum 就標為完整完成。 |
| 來源路由與單位管理 | 尚未有輸出折線專用 L05 adapter。 |
| 十組產品實例、結果監看及 Register／NVM | 尚未整合。 |
| 結果接到實體輸出 | 尚未整合，必須使用既有 SYSTEM／Safety／輸出服務。 |

可評估擴充共用 FbLinearization 的模式／Offset，或新增薄層 wrapper，內插繼續重用現有核心；不需要每 SET 複製一份演算法。具體介面須先定義下列規則。

## 尚待確認的設備行為

- 原表未給有效點數：是否固定使用十點、如何少用點，不可沿用輸入折線的十四點規則或把零值當作未使用。
- Stepped 在 Xi≤X<Xi+1 時採 Yi 還是 Yi+1？恰好落點、最末點如何處理？名稱不足以定案。
- 範圍外是否夾制、報錯或外插？重複／反序 X 如何處理？
- 三種 Off（來源功能、來源通道、動作類型）分別是輸出零、無效、保持或旁路？原表沒有說明。
- Offset 的刻度、是在轉換後相加還是其他位置、結果溢位及範圍限制如何處理？
- Output Unit=來源值單位時的來源量綱如何追蹤；若中途切換 PV／MV，點表是否仍有效？
- 輸出值為 S16 但 Offset 可將結果推過範圍，設備的飽和／錯誤政策未知。

## 建議的專案契約（尚未實作）

1. 一組 L04 實例處理一個來源數值與一張點表，組數由 L05 決定；初版產品可設定十組，但不綁定硬體。
2. X 嚴格遞增、Y 可非單調；步階可選採左端值，落在 Xi 時取 Yi，最末點取末值。此為建議，不是已確認的 DTDM04 定義。
3. 建議運算順序為轉換 → 加 Offset → 數值／設定範圍檢查；越界可採明確 CLAMP 或 ERROR。既有 Safety 許可獨立執行，不放進數學 FB。
4. 三種 Off 在產品路由層統一標成未啟用，結果零且 valid=false，不無聲旁路輸入至輸出；若將來需要旁路，應有獨立明確模式。
5. MV 及溫度分開維護刻度。專案溫度建議 0.001°C、MV 保留 0.1%；通用 float 插值仍由呼叫端指定單位，不因顯示位數改變計算。
6. 點表／模式／來源／單位／Offset 使用 Pending／Apply 驗證整組一致性；來源單位改變不能沿用未驗證點表。
7. 無效來源不得使用上次結果作為有效輸出；外層依既有輸出策略決定失效處置。
