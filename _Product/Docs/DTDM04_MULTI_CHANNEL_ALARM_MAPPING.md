# DTDM04 跨模組多通道警報對照

## 摘要

2026-10-22：依使用者提供的 Multi-channel Alarm Parameters 表（mAlm1，僅主模組存在），配合先前讀取的 DTDM04 v1.5 第 4.2.3 節（頁 4-11），確認其比較選定 PV 的 MAX−MIN，並有動作種類、動作延遲與一次性保持。

**目前沒有跨通道溫差警報 FB，尚未實作／測試。** 現有每通道三組 FbAlarm 不能直接視為已涵蓋此功能；本次只更新文件，不新增 Register、CAN 傳輸或動作分派。

以本專案架構為主：L04 接收外部提供的樣本陣列並判斷，L05 組資料／處理品質與時序，既有 SYSTEM Event／控制服務受理動作，Safety／輸出服務保留最終權責。

## 欄位對照

原位址視為十六進位，Table Index 為另一索引。本表只提供 mAlm1，不推定有第二組。產品的 8 模組×4 通道上限不寫死在通用 L04。

| 欄位 | 原位址 | 定義 |
|---|---|---|
| Input Selection module1～8 | 0x1800～1807 | 每個 word 的 bit0～3 選 CH1～4；0x00～0x0F，預設全不選。 |
| Alarm High Limit | 0x1808 | 0～9999，預設 100；溫度刻度 0.1°C／°F，類比量無單位。 |
| Action | 0x1809 | 0～16；0=Disable，其餘為既有控制動作。 |
| Delay Time | 0x180A | 0～100 個 0.1 秒，即 0～10000 ms；預設 10=1 秒。這是動作延遲，不等於單通道 Alarm 的 0～100 秒設定。 |
| Alarm Hold | 0x180B | 0／1，預設 0；啟用後警報成立只執行一次 Action，不自動復歸。 |
| Reserved | 0x180C 起 | 不推定為重置或應用通道設定。 |

比較條件為 MAX(selected PV)−MIN(selected PV)>limit，等於門檻不觸發。例如 100.000、101.500、99.500°C，溫差 2.000°C；門檻 2.000°C 不成立，1.999°C 才成立。專案溫度建議使用 0.001°C，原預設 100 代表 10.0°C，換算為 10000。

極值與差值應使用足夠位寬（例如 int64_t 差值），避免 int32_t 最大值減最小值溢位；錯誤碼與無效樣本不得參與極值。

## Alarm Hold 與單通道 Alarm 的區別

此表明確包含「Action 只作動一次」。不能只鎖存 alarm_active，卻每週期執行 Toggle／PID Group+1，否則會反覆切換或累加。

建議將輸出至少區分 condition_active（原始比較）、qualified_active（延遲後）、latched（保持）與 action_request（新的一次動作）。Action 編號和實際執行不放入數值比較核心。

- Hold=1：第一次延遲成立產生一次 action_request，保持鎖存；條件恢復後不自動重新武裝。如何人工清除仍需定義。
- Hold=0：建議每個獨立成立週期只產生一次 action_request，條件恢復後重新武裝；這是專案建議，原表沒有完整定義非保持模式的連續觸發頻率。
- Reset、Disable、設定變更、失效與恢復是否清除鎖存／允許再次動作，需分別定案。特別是來源過期不應在恢復後無意重複一次不可逆／累加型命令。

單通道 FbAlarm 的 AUTO／MANUAL／Reset 契約不能無條件套用。本表沒有多通道警報 Reset 位址，Action9～12 指向一般 Alarm，不能據此認定會清除 mAlm1 的 Hold。

## 動作與控制權責

| Action | 語意 | 本架構處理 |
|---|---|---|
| 0 | Disable | 產品路由停用；是否保留診斷比較可另外定義，不發動作。 |
| 1 | Switch SV | L05／既有控制設定服務切換指定迴路 SV。 |
| 2 | Switch Run/Stop | 提出運行模式變更請求，沿用既有狀態機。 |
| 3 | Switch Auto/Manual | 沿用既有模式切換與輸出策略。 |
| 4 | Switch AT Stop/Run | AT 協調／控制服務檢查當前模式後受理。 |
| 5／6／7 | PID Group +1／+2／−1 | PID 群組管理執行，需定義邊界及命令去重。 |
| 8 | Stop Ramping | L05 對斜率控制提出命令。 |
| 9／10／11／12 | Reset All ALM／ALM1／ALM2／ALM3 | 路由至一般 Alarm 命令；實際是否接受仍按各 Alarm 的條件判定。 |
| 13／14／15／16 | Ramp Soak Start／Stop／Advance／Hold | 程序控制服務處理；不直接操作硬體。 |

本表沒有應用通道／目標迴路欄位，不能假設 Action 自動作用到全部被比較通道。比較來源集合與動作目標集合應獨立配置；路由目標、執行成功／失敗及重試政策均待定義。

## 跨模組資料與品質

來源模組／通道選擇由 L05／通訊層解析成樣本陣列，L04 不讀 CAN／RS485 或 Register。未來採 CAN 也只改 provider 與資料管理，不改極值演算法。

待定品質政策包括：

- 至少需幾個有效且不同來源？建議少於兩個時輸出 invalid／不足資料，不以零溫差宣稱正常。
- 任一選定來源無效時整體 invalid，還是允許排除並標示 degraded？建議第一版採全部選定來源有效，避免漏掉最大／最小的失效通道。
- 遠端資料的年齡、時間戳／取樣時間差、模組離線、恢復與同序號重複樣本如何處理。
- 僅比較同一量綱且已換成共同溫度單位／刻度的值；不同 Sensor 型號可比較溫度，溫度與電流不可混比。不同類比工程量也不能因都標「無單位」就混比。
- L05 每週期可持續推進延遲，但不能把重複舊資料當作新樣本；超過資料年齡上限就必須失效。

「僅主模組存在」是產品部署與跨模組資料彙整位置，不是通用 FB 必須知道 Master／Slave 的理由。各專案可依需要建立實例；需明確指定唯一動作擁有者，避免多台同時計算卻重複執行 Action。
